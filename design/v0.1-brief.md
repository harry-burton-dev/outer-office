# Outer Office v0.1.0: build brief

The shared reference for everyone building v0.1. If code and this file disagree, fix one of them in the same change.

## What it is

A control panel for the private office of one or more senior principals. It reads each principal's Outlook calendar from an exported `.ics` file, lets the office add its own layer of preparation on top, and gives each user a small task manager. It is a Trellis app: one HTML file opened from disk, syncing through a shared folder, with no server.

Outlook is the source of truth for the diary. The app never edits imported events and never writes to Outlook.

## Scope of v0.1

In:

- Office setup and principals, editable from the admin page, with a global principal switch in the app.
- `.ics` import with a diff to review before applying. Events missing from a later export are marked gone at once.
- Calendar: day and week, diary only, read-only (FullCalendar 7, forma flavour, through shadcn).
- Engagement panel with two tabs: Overview (Outlook's fields, read-only; flag) and Prep (prep state, owner, notes, outcome).
- Tasks: Inbox, Today, one shared project with sections; quick add; assign; task panel; bin.
- Needs action drawer, for the chosen principal.
- Event log.
- Privacy notice, acknowledged once per user.

Out (designed, not built): Home and watch rules, proposals and the archive layer, saved views, exports, meeting templates, attendees, labels, comments, files, filters, project sharing by role, board view, stats.

## Data model

All fields are `latest` unless marked. Times are ISO 8601 UTC strings; dates are `YYYY-MM-DD`. Tables sync independently, so every screen must tolerate a reference whose record has not arrived.

| Table | Fields |
|---|---|
| `office` (one record, id `office`) | `name`, `timezone` (IANA), `dayStart`, `dayEnd` ("08:00"), `privatePolicy` (`drop` or `mask`) |
| `principals` | `code`, `title`, `order` (number), `active` (boolean) |
| `people` | `userId`, `mode` (`assistant` or `viewer`), `privacyAckAt` |
| `events` | `principal`, `uid`, `recurrenceId`, `start`, `end`, `allDay` (boolean), `subject`, `location`, `organizer`, `categories`, `showAs`, `masked` (boolean), `gone` (boolean), `sourceModified`, `moves` (number), `importId` |
| `overlays` (id `tx.id("overlay", eventId)`) | `event`, `prep` (`none`, `needed`, `in-hand`, `ready`), `flagged` (boolean), `prepOwner` (ask), `notes` (text), `outcome` (text) |
| `projects` | `name`, `owner`, `order` (number), `inbox` (boolean), `archived` (boolean). Each user's Inbox has id `tx.id("inbox", userId)` |
| `sections` | `project`, `name`, `order` (number) |
| `tasks` | `title`, `notes` (text), `project`, `section`, `order` (number, fractional index), `priority` (1 to 4), `due`, `deadline` (ask), `done` (boolean), `doneAt`, `doneBy`, `assignee` (ask), `assignedBy`, `assignment` (`none`, `offered`, `accepted`, `declined`), `principal` (optional tag), `event` (optional link), `createdAt`, `createdBy` |
| `log` (append-only, random ids) | `at`, `by`, `principal`, `area` (`calendar`, `overlay`, `task`, `import`, `setup`), `kind`, `event`, `task`, `from`, `to`, `note` |
| `imports` | `principal`, `at`, `by`, `rangeStart`, `rangeEnd`, `added`, `changed`, `gone` |

## Commands

Commands are the only writers. A handler gets no clock: every command takes `now` (an ISO string) in its input. A handler's reads are a snapshot taken when it starts. Predictable ids come from `tx.id(...)`.

| Command | Does |
|---|---|
| `office.save` | Sets the office record's fields |
| `principal.save` | Creates or changes a principal. A new one has id `tx.id("principal", code)` |
| `import.apply` | Applies a confirmed diff to `events`; one `imports` record; one `log` row per event added, moved, changed, gone or returned, and one for the import |
| `overlay.set` | Creates or updates an event's overlay; one `log` row when prep or the flag changes |
| `task.add` | New task, into the user's Inbox unless a project is given |
| `task.update` | Title, notes, priority, due, deadline, principal, project, section |
| `task.move` | Order or section |
| `task.complete` | Completes or reopens |
| `task.assign` | Assign, accept, decline or recall |
| `task.link` | Links or unlinks an engagement |
| `task.remove` | To the bin, or back |
| `project.save`, `section.save` | Create, rename, reorder, archive |
| `people.ackPrivacy` | Records that the user read the privacy notice |

Every `task.*` command writes exactly one `log` row in the same run.

### Import rules

- An event's id is `tx.id("event", principalId, uid)` for a single event and `tx.id("event", principalId, uid, recurrenceId)` for one occurrence of a series (the framework refuses an empty id part), so repeat and concurrent imports converge. Use the `eventId` helper in `app/src/domain/commands/import.ts`.
- An event is updated only if the file's `LAST-MODIFIED` is not older than the stored `sourceModified`.
- An event inside the file's date range that the file no longer contains is marked `gone`. Its overlay and tasks stay.
- A gone event that reappears has `gone` cleared and a `returned` log row.
- `CLASS:PRIVATE` and `CONFIDENTIAL` items are dropped, or stored with subject "Private, busy" and no location or organiser, by `office.privatePolicy`. This happens before anything is written.
- When an event's start changes, `moves` goes up by one.

### Assignment states

| State | Ways out |
|---|---|
| `none` | Assign to someone → `offered`. Assign to yourself → `accepted`. |
| `offered` | Assignee accepts → `accepted`. Assignee declines → `declined`. Assigner recalls → `none`. |
| `accepted` | Assignee hands back → `declined`. Assigner recalls → `none`. |
| `declined` | Assigner reassigns → `offered`. Assigner clears → `none`. |

Completing is separate: any state can be completed and reopened.

## Screens

| Screen | Notes |
|---|---|
| Frame | Left navigation: the principal switch, then Calendar, Import, Log (these follow the switch); then Inbox, Today and the project (these never do). Top bar: Add task, Needs action, sync indicator, user. |
| Calendar | Default screen once a principal exists. Week and day. Clicking an event opens the engagement panel. |
| Engagement panel | Right-hand sheet. Tabs: Overview, Prep. |
| Import | Choose principal and file, review the diff, apply, then a reminder to delete the export file. Import history. |
| Task list | Inbox, Today, or the project grouped by section. |
| Task panel | Right-hand sheet. |
| Quick add | A dialog opened with Q or the Add task button. Reads `#project`, `/section`, `p1` to `p4`, `+person`, `^PRINCIPAL`, a date in plain words, and a deadline in braces. |
| Needs action | Right-hand drawer: tasks tagged to the chosen principal that are overdue or due today, engagements in the next 24 hours that still need prep, and gone engagements that have office data. |
| Log | Newest first, filterable by area. |
| Privacy notice | A dialog before Tasks opens for the first time. |
| Empty states | No principals: point to the admin page. Principal with no import: point to Import. |

Viewer mode (`people.mode` is `viewer`) hides every write control. It is not a security boundary: Trellis has one key per workspace.

## Rules for code

- TypeScript. No `any`. Named prop interfaces. No `console.log`.
- Never mutate: build new objects.
- Screens read with the framework's hooks and write with commands. A screen never touches the engine or a file.
- Files under 400 lines; functions under 50.
- Tests first. Arrange, act, assert. Names that say the behaviour.
- All test data is synthetic. No real names, addresses or diary content. Principal codes in examples are `PRINCIPAL-A` and `PRINCIPAL-B`.
- Conventional commit messages.
